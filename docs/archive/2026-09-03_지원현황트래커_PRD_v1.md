# 지원 현황 트래커 PRD

## 1. 문서 개요

- 문서명: 지원 현황 트래커 PRD
- 제품 유형: 개인용 취업 지원 관리 웹 서비스
- 1차 개발 범위: Desktop Web MVP
- 초기 사용자: 1인 개인 사용자
- 확장 방향: 향후 다중 사용자 배포 가능 구조 고려
- 메인 진입 화면: **지원 내역(지원 공고 목록)**

---

## 2. 서비스 한 줄 정의

지원한 기업과 포지션, 지원 날짜, 전형 진행 상황, 단계별 결과 및 날짜를 한 곳에 기록하고, 지원 현황과 단계별 합격률을 확인할 수 있는 개인용 취업 지원 관리 서비스.

---

## 3. 문제 정의

취업 지원을 여러 채용 플랫폼과 기업 홈페이지에서 동시에 진행하면 다음 문제가 발생한다.

1. 총 몇 개 기업에 지원했는지 한눈에 확인하기 어렵다.
2. 동일 기업에 과거 지원한 사실을 놓치기 쉽다.
3. 기업마다 전형 단계와 순서가 달라 진행 상황을 일관되게 기록하기 어렵다.
4. 서류, 면접, 과제 등 각 전형의 합격/불합격 날짜를 별도로 기억하기 어렵다.
5. 내가 어느 단계에서 높은 혹은 낮은 합격률을 보이는지 확인하기 어렵다.
6. 면접 일정과 결과 발표 날짜가 섞여 있어 이후 지원 패턴을 분석하기 어렵다.

본 서비스는 위 문제를 해결하기 위해 **지원 기록 관리 + 전형 단계 추적 + 중복 지원 확인 + 합격률 시각화**에 집중한다.

---

## 4. 제품 목표

### 4.1 MVP 목표

- 지원한 기업을 빠르게 등록할 수 있다.
- 지원 내역을 날짜순으로 한눈에 확인할 수 있다.
- 기업별 전형 단계를 자유롭게 구성할 수 있다.
- 단계별 상태와 날짜를 자동 기록할 수 있다.
- 단계별 합격률을 확인할 수 있다.
- 과거 동일 기업 지원 이력을 확인할 수 있다.
- 사용자가 직접 날짜와 상태를 수정할 수 있다.

### 4.2 MVP에서 하지 않는 것

아래 기능은 초기 버전에서 제외한다.

- 복잡한 회원가입/소셜 로그인
- 채용 플랫폼 자동 연동
- 이메일 자동 파싱
- 공고 자동 수집
- AI 자기소개서 생성
- 연봉, 근무지역, 복지 등 상세 채용 DB
- 모바일 우선 최적화
- 변경 이력 전체 보존
- 장기 지원 데이터 분석 고도화

## 5. 사용자 및 인증 구조

### 5.1 초기 사용자

- 우선 1인 개인 사용자를 대상으로 한다.
- 이후 외부 배포 가능성을 고려한다.

### 5.2 기록 저장 및 불러오기

초기에는 복잡한 회원가입 대신 간단한 비밀번호 기반 접근 방식을 사용한다.

#### 요구사항

- 사용자가 최초 사용 시 기록 저장용 비밀번호를 설정할 수 있다.
- 재접속 시 비밀번호를 입력하여 기존 데이터를 불러올 수 있다.
- 새 기록으로 시작하는 기능을 제공한다.
- 비밀번호는 데이터 식별자 그 자체로 사용하지 않는다.
- 내부적으로 별도의 사용자 식별 ID를 생성하고, 비밀번호는 인증 수단으로 사용한다.

#### 기본 진입 UX 예시

- 새로 시작하기
- 내 기록 불러오기

## 6. 정보 구조

PC 버전 기준으로 화면 내 중복 네비게이션을 최소화한다.

### 6.1 상단 바

상단 바에는 주요 액션만 배치한다.

- 서비스명 / 로고
- 내 기록 불러오기
- 기록 추가
- 사용자/설정 진입

### 6.2 좌측 사이드바

좌측 사이드바가 주요 카테고리 내비게이션 역할을 한다.

- 지원 내역 **(메인 홈 / 기본 진입 화면)**
- 대시보드 또는 통계
- 캘린더
- 메모
- 설정
- 도움말

> 상단 바와 좌측 사이드바에 동일 카테고리 메뉴를 중복 배치하지 않는다.

## 7. 메인 홈 화면: 지원 내역

메인 홈은 별도 대시보드 페이지가 아니라 **지원 내역 목록 화면**이다.

화면 상단에는 핵심 KPI와 단계별 합격률을 요약하여 보여주고, 하단에 실제 지원 기업 목록을 배치한다.

### 7.1 상단 KPI

필수 KPI:

- 총 지원
- 진행 중
- 불합격
- 최종 합격
- 이번 달 지원

#### KPI 정의

- 총 지원: 등록된 전체 지원 기록 수
- 진행 중: 최종 결과가 확정되지 않았고 지원철회 상태가 아닌 기록 수
- 불합격: 최종적으로 불합격 처리된 지원 기록 수
- 최종 합격: 최종 합격 상태인 기록 수
- 이번 달 지원: 현재 월에 지원일이 포함되는 기록 수

---

## 8. 단계별 합격률

메인 화면 KPI 하단에 단계별 합격률을 보여준다.

### 8.1 표시 방식

- 숫자 카드 + 작은 Progress Bar
- 단계별 퍼센트와 분자/분모를 함께 노출 가능

예시:

- 서류 합격률 64% (16 / 25)
- 1차 면접 57% (12 / 21)
- 과제 전형 50% (8 / 16)
- 임원 면접 40% (4 / 10)

### 8.2 계산 기준

MVP에서는 **결과가 나온 전형만 분모에 포함한다.**

```text
단계별 합격률 = 해당 단계 합격 건수 / 해당 단계에서 합격 또는 불합격 결과가 확정된 건수 × 100
```

예:

- 서류 결과 확정 10건
- 서류 합격 4건
- 서류 불합격 6건
- 서류 합격률 = 40%

`예정`, `결과대기`, `지원철회` 상태는 합격률 분모에서 제외한다.

### 9.1 기본 정렬

- 지원일 최신순
- 동일 날짜의 경우 최근 생성된 기록 우선

### 9.2 PC 테이블 컬럼

- 기업명
- 지원 포지션
- 지원일

### 9.4 목록 수정 정책

- 목록에서는 상태를 직접 수정하지 않는다.
- 모든 수정은 상세 페이지에서 진행한다.

## 11. 지원 기록 추가

### 11.1 진입 방식

- 메인 화면 우측 상단 `기록 추가` 버튼 클릭
- 별도 페이지 이동 없이 **우측 Drawer** 오픈

### 11.2 필수/선택 입력값

#### 필수

- 기업명
- 지원 포지션
- 지원일

#### 선택

- 공고 URL
- 기업 메모

### 11.3 지원일 기본값

- 새로운 지원 기록 생성 시 `지원일 = 등록 시점의 오늘 날짜`
- 사용자가 직접 날짜 수정 가능

## 12. 중복 지원 감지

동일 기업에 대한 과거 지원 이력을 확인할 수 있어야 한다.

### 12.1 중복 판단 기준

MVP 기준:

- 기업명이 동일하면 중복 가능성이 있는 것으로 판단
- 포지션이 다르더라도 과거 지원 이력은 알림

### 12.2 동작 방식

기업명 입력 시 기존 지원 기록을 검색한다.

과거 동일 기업 기록이 존재하면 Drawer 내에 안내를 표시한다.

예시:

```text
동일 기업 지원 이력이 있습니다.
토스 · Product Manager · 2026.05.24
[기록 보기]
```

### 12.3 저장 시 확인

사용자가 저장 버튼을 클릭할 때 중복 기록이 존재하면 확인 팝업을 표시한다.

예시:

```text
동일 기업에 지원한 기존 기록이 있습니다.
2026.05.24 · Product Manager · 서류 불합격

그래도 새 지원 기록을 등록하시겠습니까?

[취소] [계속 등록]
```

- 중복이어도 등록은 가능하다.
- 중복은 차단 조건이 아니라 안내 조건이다.

## 13. 기업별 전형 단계 설정

기업마다 채용 절차가 다르므로 전형 단계를 고정하지 않는다.

### 13.1 기본 전형 템플릿

새 지원 등록 시 아래 기본값을 제공한다.

1. 서류
2. 1차 면접
3. 과제 전형
4. 임원 면접
5. 최종 결과

### 13.2 사용자가 가능한 작업

- 단계명 수정
- 단계 추가
- 단계 삭제
- 단계 순서 변경

### 13.3 UI

지원 기록 추가 Drawer 안에 `전형 단계 설정` 영역을 제공한다.

- 기본적으로 접혀 있어도 됨
- 펼치면 단계 목록 노출
- 드래그 앤 드롭 또는 위/아래 이동 방식으로 순서 변경

## 14. 상태값 정책

지원 접수와 개별 전형 상태를 구분한다.

### 14.1 지원 접수 상태

지원 직후 서류 접수 단계에서 사용할 수 있는 상태:

- 지원완료
- 원서 확인

### 14.2 전형 공통 상태

서류 이후 각 단계에서 사용할 수 있는 상태:

- 예정
- 결과대기
- 합격
- 불합격
- 지원철회

### 14.3 상태 정의

#### 예정

- 향후 전형 일정이 확정되었거나 진행 전 상태

#### 결과대기

- 면접, 과제, 서류 검토 등 해당 전형은 진행되었고 결과를 기다리는 상태

#### 합격

- 해당 전형 통과

#### 불합격

- 해당 전형 탈락

#### 지원철회

- 사용자가 지원을 중단한 상태
- 합격률 계산에서 제외

## 15. 날짜 기록 정책

각 단계는 최소 아래 두 종류의 날짜를 지원한다.

### 15.1 전형 진행일

실제로 면접, 과제 제출 등 해당 단계가 진행된 날짜.

예:

- 1차 면접일
- 과제 제출일
- 임원 면접일

### 15.2 결과일

합격 또는 불합격 결과를 확인한 날짜.

예:

- 서류 합격일
- 면접 합격일
- 과제 불합격일

---

## 16. 날짜 자동 기록 로직

### 16.1 지원 등록

```text
지원 기록 생성 시
지원일 = 오늘 날짜
```

사용자가 직접 수정 가능.

### 16.2 상태 변경

상태를 `합격` 또는 `불합격`으로 변경할 경우:

```text
결과일 = 상태 변경 날짜
```

자동 입력한다.

### 16.3 MVP 재변경 정책

예:

```text
결과대기 → 합격 → 결과대기 → 합격
```

MVP에서는 최종 상태 변경 시점의 날짜로 결과일을 덮어쓴다.

과거 변경 이력 전체 저장은 V2에서 고려한다.

### 16.4 수동 수정

- 자동 입력된 날짜는 언제든 수정 가능
- 수정 버튼 또는 날짜 입력 UI 제공

---

## 17. 면접 일정 우선 노출 정책

면접 전형에서는 결과일보다 실제 면접일이 사용자에게 더 중요하다.

### 목록/요약 화면

우선 노출:

```text
1차 면접
2026.09.10 14:00
```

### 상세 화면

추가 정보:

```text
면접일: 2026.09.10 14:00
합격 결과일: 2026.09.12
```

결과일은 상세 정보 또는 통계 계산 용도로 활용한다.

### 18.1 상단 정보

예시:

```text

│

● 1차 면접
  예정

│

○ 과제 전형
  예정

│

○ 임원 면접
  예정
```

### 18.3 단계별 표시 정보

각 단계에서 지원할 수 있는 정보:

- 단계명
- 상태
- 전형 진행일
- 결과일
- 전형별 메모

## 19. 메모 기능

메모는 2종류를 지원한다.

### 19.1 기업 전체 메모

기업 또는 지원 건 전체에 대한 메모.

예:

- 기업 문화
- 준비 포인트
- 공고 핵심 요구사항

### 19.2 전형별 메모

각 전형 단계에서 별도로 작성 가능.

예:

```text
서류
포트폴리오에서 데이터 지표 강조

1차 면접
사용자 문제 정의 관련 질문이 많았음

과제 전형
3시간 내 서비스 개선안 제출
```

## 27. 현재 단계 계산

현재 단계는 각 Application에 속한 Stage 중 아직 완료되지 않은 가장 앞 단계 기준으로 판단한다.

예:

```text
서류 = passed
1차 면접 = waiting
과제 = scheduled

→ 현재 단계 = 1차 면접
```

최종 합격 또는 최종 불합격 처리된 경우 해당 상태를 우선한다.

---

## 28. 진행 중 계산

아래 조건이면 `진행 중`으로 본다.

- 최종 결과가 아직 확정되지 않음
- 지원철회 상태가 아님
- 어느 단계라도 예정 / 결과대기 / 지원완료 / 원서확인 상태가 존재

---

## 29. 주요 예외 케이스

### 29.1 전형 단계 건너뛰기

기업에 따라 과제 또는 임원 면접이 없을 수 있다.

→ 해당 단계 삭제 가능.

### 29.2 동일 기업 다른 포지션

같은 기업 + 다른 포지션 지원 가능.

→ 중복 알림은 표시하되 저장 허용.

### 29.3 동일 기업 동일 포지션 재지원

재지원 가능.

→ 과거 지원일과 결과를 팝업으로 안내.

### 29.4 날짜 역전

예:

- 면접일: 09.10
- 결과일: 09.08

이 경우 경고를 표시한다.

```text
결과일이 전형 진행일보다 빠릅니다. 날짜를 확인해주세요.
```

강제 차단 여부는 개발 편의에 따라 결정 가능하나 MVP에서는 경고 후 저장 허용 가능.

### 29.5 지원일보다 전형일이 빠른 경우

경고 노출.

### 29.6 지원철회

지원철회 이후 다음 전형은 비활성 상태로 처리 가능.

## 30. MVP 완료 기준

아래 항목이 모두 동작하면 1차 MVP 완료로 판단한다.

- 동일 기업 중복 경고

- 전형 진행일 기록
- 합격/불합격 시 결과일 자동 입력
- 자동 날짜 수동 수정
- 지원 내역 최신순 정렬
- 기업명 검색
- 상태/단계/포지션 필터
- 총 지원 / 진행 중 / 불합격 / 최종 합격 / 이번 달 지원 KPI
- 단계별 합격률 계산
- 기업 상세 페이지

## 31. Claude 개발 요청용 요약 프롬프트

아래 요구사항을 기준으로 Desktop-first 웹 서비스를 구현한다.

- 서비스명: 지원 현황 트래커
- 메인 홈: 별도 대시보드가 아니라 `지원 내역` 목록
- 상단에 KPI와 단계별 합격률 요약
- 하단에 지원 기업 테이블
- 기록 추가는 우측 Drawer
- 상세 페이지는 세로 Timeline
- 동일 기업 중복 지원 경고
- 기업별 전형 단계 커스터마이징
- 날짜 자동 기록 및 수동 수정
- 단계별 합격률은 결과 확정 건만 기준
- PC 우선
- 디자인은 정돈된 SaaS + 약간 따뜻한 생산성 도구 스타일
- 메인 컬러는 보랏빛이 살짝 도는 muted navy / blue
- 상단 바와 좌측 내비게이션의 메뉴 중복 금지

구현 우선순위는 기능 정확성 > 정보 구조 > 디자인 디테일 순서로 진행한다.
