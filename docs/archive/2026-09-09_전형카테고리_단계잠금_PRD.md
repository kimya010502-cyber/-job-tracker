# CatchPass — 전형 카테고리 고정 및 단계 잠금 로직 PRD

## 0. 문서 목적

본 문서는 CatchPass의 전형 관리 구조를 안정화하기 위해 아래 두 가지 핵심 개선사항을 정의한다.

1. **전형 카테고리 표준화**
2. **앞 전형 미통과 시 뒷 전형 잠금**

이번 개선은 이후 통계 대시보드 정확도와 메인 화면의 현재 단계 표시 오류를 방지하기 위한 선행 작업이다.

---

# 1. 개선 배경

현재 CatchPass에서는 사용자가 전형명을 직접 작성할 수 있어 다음 문제가 발생할 수 있다.

- `1차 면접`, `1차면접`, `실무 면접` 등이 서로 다른 전형으로 집계될 수 있음
- 전형별 통과율 / 평균 소요시간 계산이 불안정함
- 앞 전형이 통과되지 않았는데도 뒤 전형에 데이터가 존재하면 메인 화면에서 뒤 전형이 현재 단계로 노출되는 오류가 발생할 수 있음
- 사용자가 이전 전형 결과를 수정했을 때 후속 전형 데이터와 현재 단계가 불일치할 수 있음

따라서 전형 카테고리를 표준화하고, 전형 순서 및 통과 여부를 기준으로 단계 활성화 조건을 명확히 정의한다.

---

# 2. 전형 카테고리 표준화

## 2.1 기본 제공 전형 카테고리

기록 추가 및 상세 수정 화면에서 사용자는 아래 옵션 중 하나를 선택한다.

1. 서류
2. 1차 면접
3. 2차 면접
4. 과제 전형
5. 임원 면접
6. 처우 협의
7. 최종 결과
8. 직접 입력

기존 기본 전형 구성은 유지한다.

```text
서류
→ 1차 면접
→ 과제 전형
→ 임원 면접
→ 최종 결과
```

추가 옵션인 `2차 면접`, `처우 협의`는 사용자가 필요 시 단계 추가를 통해 선택한다.

---

## 2.2 직접 입력

사용자가 원하는 전형명이 기본 옵션에 없는 경우 `직접 입력`을 선택한다.

`직접 입력` 선택 시에만 별도 텍스트 입력창을 활성화한다.

예:

```text
전형 유형: 직접 입력
전형명: 컬처핏 인터뷰
```

또는:

```text
전형 유형: 직접 입력
전형명: 인성검사
```

---

# 3. 데이터 구조

표시되는 전형명과 통계용 전형 카테고리를 분리한다.

예시:

```text
display_name = "1차 면접"
stage_category = "FIRST_INTERVIEW"
```

직접 입력:

```text
display_name = "컬처핏 인터뷰"
stage_category = "CUSTOM"
```

권장 `stage_category` 값:

```text
DOCUMENT
FIRST_INTERVIEW
SECOND_INTERVIEW
ASSIGNMENT
EXECUTIVE_INTERVIEW
COMPENSATION
FINAL_RESULT
CUSTOM
```

---

# 4. 기존 데이터 마이그레이션

기존에 저장된 전형 데이터는 가능한 경우 자동 매핑한다.

예:

```text
서류 → DOCUMENT
1차 면접 → FIRST_INTERVIEW
과제 전형 → ASSIGNMENT
임원 면접 → EXECUTIVE_INTERVIEW
최종 결과 → FINAL_RESULT
```

기존 데이터 중 정확히 매핑되지 않는 전형명은:

```text
stage_category = CUSTOM
display_name = 기존 전형명
```

으로 유지한다.

기존 사용자 데이터는 삭제하지 않는다.

---

# 5. 전형 단계 순서

사용자는 기존처럼 전형 단계 순서를 변경할 수 있다.

예:

```text
서류
→ 과제 전형
→ 1차 면접
→ 2차 면접
→ 임원 면접
→ 처우 협의
→ 최종 결과
```

따라서 **전형 카테고리와 전형 순서는 서로 독립적으로 관리**한다.

순서는 `order_index` 기준으로 판단한다.

---

# 6. 단계 활성화 기본 원칙

현재 전형 단계의 수정 가능 여부는 **바로 앞 단계의 결과**를 기준으로 판단한다.

핵심 규칙:

> 첫 번째 전형은 항상 활성화한다.  
> 두 번째 전형부터는 바로 앞 전형의 상태가 `통과`일 때만 활성화한다.

---

# 7. 단계 잠금 로직

예:

```text
1. 서류
2. 1차 면접
3. 과제 전형
4. 임원 면접
5. 최종 결과
```

## 7.1 서류가 통과 전인 경우

서류 상태:

- 접수완료
- 서류 확인
- 결과 대기

중 하나라면:

```text
서류        활성화
1차 면접    잠금
과제 전형   잠금
임원 면접   잠금
최종 결과   잠금
```

1차 면접 이하 단계의 입력값은 수정할 수 없다.

---

## 7.2 서류 통과 후

서류 상태:

```text
통과
```

이면:

```text
서류        활성화
1차 면접    활성화
과제 전형   잠금
임원 면접   잠금
최종 결과   잠금
```

---

## 7.3 1차 면접 통과 후

```text
서류        통과
1차 면접    통과
```

이면:

```text
과제 전형 활성화
```

이후 동일한 방식으로 순차 활성화한다.

---

# 8. 잠금 상태 UI

잠긴 전형은 화면에서 숨기지 않는다.

사용자가 전체 채용 프로세스를 파악할 수 있도록 기존 단계는 그대로 표시한다.

대신 다음 처리를 적용한다.

- 입력 필드 disabled
- 상태값 변경 불가
- 날짜 변경 불가
- 메모 변경 불가
- 시각적으로 낮은 강조도 사용
- 잠금 아이콘 표시 가능

안내 문구:

```text
이전 전형을 통과하면 입력할 수 있습니다.
```

---

# 9. 기존 뒷 전형 데이터 처리

현재 문제 상황처럼 앞 전형이 통과되지 않았지만 이미 뒤 전형에 데이터가 저장되어 있을 수 있다.

이 경우 **기존 데이터를 삭제하지 않는다.**

예:

```text
서류: 결과 대기
1차 면접: 2026.09.12 / 결과 대기
```

정상 동작:

- 1차 면접 데이터는 DB에 유지
- UI에서는 1차 면접을 잠금 처리
- 메인 현재 단계는 `서류`
- 사용자는 서류가 통과되기 전까지 1차 면접 데이터를 수정할 수 없음

---

# 10. 이전 전형 결과 변경

이미 앞 전형이 통과되어 뒤 단계가 활성화된 이후 사용자가 앞 전형 결과를 변경할 수 있다.

예:

기존:

```text
서류: 통과
1차 면접: 결과 대기
```

사용자가 서류를:

```text
통과 → 탈락
```

으로 변경.

처리 결과:

- 1차 면접 데이터 삭제 금지
- 1차 면접 잠금
- 그 뒤 모든 단계 잠금
- 현재 단계는 `서류`로 변경
- 지원 건 전체 상태는 `종료`
- 과거 입력값은 그대로 보존

---

# 11. 현재 단계 계산 로직

현재 단계는 **가장 뒤에 데이터가 존재하는 단계**로 판단하지 않는다.

반드시 전형 순서와 통과 여부를 기준으로 계산한다.

## 계산 방식

1. `order_index` 순서대로 전형 확인
2. 첫 번째 전형부터 시작
3. 현재 단계가 `통과`이면 다음 단계로 이동
4. 현재 단계가 `통과`가 아니면 해당 단계에서 중단
5. 해당 단계가 메인 화면의 `현재 단계`

예:

```text
서류: 통과
1차 면접: 결과 대기
과제 전형: 기존 데이터 있음
```

현재 단계:

```text
1차 면접
```

과제 데이터 존재 여부는 현재 단계 계산에 영향을 주지 않는다.

---

# 12. 현재 단계 예외 처리

## 탈락

현재 단계가 `탈락`이면:

- 해당 단계가 최종 현재 단계
- 이후 단계 잠금
- 지원 건 전체 상태 = 종료

## 철회

현재 단계가 `철회`이면:

- 해당 단계에서 프로세스 종료
- 이후 단계 잠금
- 지원 건 전체 상태 = 종료

## 최종 결과

최종 결과가:

- 최종 합격
- 최종 탈락
- 철회

중 하나이면 프로세스 종료.

---

# 13. 통계 영향

전형 카테고리 표준화를 통해 이후 통계는 `display_name`이 아닌 `stage_category`를 기준으로 계산한다.

예:

```text
FIRST_INTERVIEW
```

카테고리 기준으로:

- 통과율
- 탈락률
- 평균 소요시간
- 결과 확정 건수

등을 집계한다.

`CUSTOM` 전형은 기본 대시보드 전형 통과율에서 제외하거나 별도 `기타`로 묶을 수 있다.

초기 권장안:

> CUSTOM 전형은 기본 통과율 카드에서 제외한다.

---

# 14. 메인 화면 데이터 원칙

메인 화면의 `현재 단계`는 본 PRD의 단계 활성화 / 현재 단계 계산 규칙을 따른다.

예:

```text
서류 결과 대기
```

인데 1차 면접 날짜가 과거에 입력되어 있더라도:

```text
현재 단계 = 서류
```

로 표시한다.

---

# 15. 메인 상단 KPI 구조

메인 지원 내역 화면의 상단 데이터는 **현재 및 이번 달 중심**으로 구성한다.

노출 항목:

1. 이번 달 지원
2. 진행 중
3. 이번 달 불합격
4. 최종 합격

누적 총 지원 수 및 상세 분석 데이터는 통계 탭에서 제공한다.

---

# 16. 통계 탭 구조

전형 카테고리 고정 및 단계 잠금 로직 적용 후 통계 탭을 아래 순서로 구성한다.

## 1. 전체 지원 현황

- 총 지원
- 진행 중
- 누적 탈락
- 최종 합격

## 2. 월별 지원 추이

- 최근 3개월 지원 건수
- 라인차트
- 최근 3개월 총 지원
- 전월 동기간 대비 %

동기간 비교 예:

현재 날짜가 9월 9일이라면:

```text
9월 1일 ~ 9월 9일
vs
8월 1일 ~ 8월 9일
```

로 비교한다.

## 3. 전형 통과율

대상:

- 서류
- 1차 면접
- 2차 면접
- 과제 전형
- 임원 면접
- 필요 시 최종 합격률

계산:

```text
통과 ÷ (통과 + 탈락) × 100
```

아래 상태는 분모에서 제외:

- 접수완료
- 서류 확인
- 진행 전
- 결과 대기
- 철회

## 4. 전형 소요시간

전형 순서가 아니라 `stage_category`별로 계산한다.

예:

- 서류: 지원일 → 서류 결과일
- 1차 면접: 면접일 → 해당 면접 결과일
- 2차 면접: 면접일 → 해당 면접 결과일
- 과제 전형: 과제 제출일 → 결과일
- 임원 면접: 면접일 → 결과일
- 처우 협의: 협의 시작일 → 최종 확정일

## 5. 지원 포지션 분석

- 포지션별 지원 수
- 포지션별 서류 통과율

---

# 17. 구현 우선순위

다음 순서로 개발한다.

### Step 1
전형 카테고리 고정 및 직접 입력 구조 적용

### Step 2
기존 데이터 stage_category 마이그레이션

### Step 3
앞 전형 통과 여부 기반 단계 잠금 적용

### Step 4
현재 단계 계산 로직 수정

### Step 5
메인 화면 KPI 수정

### Step 6
통계 탭 신규 구조 적용

이 순서를 유지해야 통계가 기존 불안정한 전형명 또는 잘못된 현재 단계 데이터를 기반으로 계산되는 것을 방지할 수 있다.

---

# 18. Claude 구현 지시사항

```text
기존 CatchPass 기능과 UI를 최대한 유지하면서
전형 데이터 구조와 단계 활성화 로직을 수정해줘.

[전형 카테고리]

기본 옵션:
- 서류
- 1차 면접
- 2차 면접
- 과제 전형
- 임원 면접
- 처우 협의
- 최종 결과
- 직접 입력

직접 입력을 선택했을 때만 전형명 텍스트 입력 필드를 활성화한다.

display_name과 stage_category를 분리한다.

stage_category:
DOCUMENT
FIRST_INTERVIEW
SECOND_INTERVIEW
ASSIGNMENT
EXECUTIVE_INTERVIEW
COMPENSATION
FINAL_RESULT
CUSTOM

기존 데이터도 가능한 범위에서 자동 매핑하고,
매핑 불가능한 값은 CUSTOM으로 유지한다.

[단계 잠금]

첫 전형은 항상 활성화한다.
두 번째 전형부터는 바로 앞 전형이 "통과" 상태일 때만 활성화한다.

앞 전형이 통과가 아니면 이후 단계는 disabled 처리한다.

잠긴 단계의 기존 데이터는 절대로 삭제하지 않는다.

앞 전형이 과거에 통과였다가 탈락/철회 등으로 변경된 경우에도
뒤 단계 데이터는 유지하되 다시 잠근다.

[현재 단계]

현재 단계는 뒤 단계에 날짜나 상태 데이터가 존재하는지를 기준으로 계산하지 않는다.

order_index 순서대로 확인하고,
첫 번째로 "통과"가 아닌 단계를 현재 단계로 사용한다.

예:
서류 통과
1차 면접 결과 대기
과제 데이터 존재

=> 현재 단계는 1차 면접

[메인 KPI]

메인 화면 상단:
- 이번 달 지원
- 진행 중
- 이번 달 불합격
- 최종 합격

[통계]

통계 화면 순서:
1. 전체 지원 현황
2. 월별 지원 추이
3. 전형 통과율
4. 전형 소요시간
5. 지원 포지션 분석

통계 집계는 display_name이 아닌 stage_category 기준으로 계산한다.

기존 검색, 필터, 자동 상태 전환, 중복 지원 경고,
사용자별 데이터 저장 및 인증 기능을 깨뜨리지 않는다.
```

# 19. 완료 기준

다음 조건을 모두 만족하면 본 개선 완료로 판단한다.

- 전형 선택 옵션이 표준 카테고리 방식으로 변경됨
- 직접 입력 옵션 정상 작동
- 기존 데이터가 카테고리로 마이그레이션됨
- 앞 전형 미통과 시 뒤 전형 수정 불가
- 뒤 전형 기존 데이터 유지
- 앞 단계 결과 변경 시 뒤 단계 자동 잠금
- 현재 단계가 앞 전형 통과 여부 기준으로 정확하게 계산됨
- 뒤 단계의 기존 값 때문에 현재 단계가 잘못 이동하지 않음
- 메인 상단 KPI가 이번 달/현재 중심으로 변경됨
- 통계 집계가 표준 전형 카테고리 기준으로 동작함
